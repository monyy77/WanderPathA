# Use Case: Flight Delay Handling with Rebooking and Compensation

## Overview

WanderPathA is an autonomous travel assistant designed to help airline operation teams handle flight disruptions.

This use case focuses on a common airline **Irregular Operations (IROPS)** scenario: a flight delay that affects passengers' journeys and requires the system to analyze the situation, identify affected customers, evaluate possible solutions, and provide a suitable recommendation including rebooking and compensation decisions.

The system combines:
- MCP-based tool execution for accessing real operational data.
- Planning and reasoning strategies for complex decision-making.
- Memory and RAG components for maintaining context and retrieving airline policies.
- Grounded execution to ensure recommendations are based on real database information.

---

## Scenario

A flight is delayed due to an operational issue such as bad weather. Some passengers may miss connections or require alternative travel arrangements.

The airline agent receives a request:

```
Handle the disruption of flight 2.
Identify affected customers, evaluate alternatives,
determine compensation, and provide a final recommendation.
```

The system should:

1. Check the flight status and delay information.
2. Identify passengers affected by the disruption.
3. Analyze passenger priorities.
4. Retrieve relevant airline policies.
5. Find available alternatives.
6. Select the best rebooking option.
7. Calculate compensation if applicable.
8. Generate a final recommendation.

## Step-by-Step Explanation

### 1. Customer Request

The process starts when the user or airline employee submits a disruption-handling request.

Example:

```
Flight 2 has a 120-minute delay because of bad weather.
Identify affected bookings, evaluate alternatives,
and recommend the best solution.
```

The request contains the goal that the autonomous agent needs to solve.

---

### 2. Flight Delay / Disruption Detection

The agent analyzes the request and determines that it is an operational disruption scenario.

The system retrieves flight information using MCP tools:

Examples:
- Flight status lookup.
- Delay reason retrieval.
- Connection risk identification.

The information is obtained from the airline database instead of being generated by the language model.

---

### 3. Autonomous Agent Processing

The WanderPathA Agent receives the user goal and decides how the problem should be handled.

The agent coordinates between:
- Planning Layer.
- MCP Tools.
- Database.
- Memory.
- Retrieval components.
- Execution pipeline.

The agent does not directly guess an answer; it creates an execution strategy based on the available information.

---

### 4. Task Decomposition

For complex disruption scenarios, the Planning Agent breaks the main goal into smaller executable tasks.

Example decomposition:

```
Goal:
Handle flight delay and provide passenger recommendations.

Task 1: Check flight status.
Task 2: Find affected bookings.
Task 3: Analyze passenger priority.
Task 4: Retrieve alternative flights.
Task 5: Choose suitable rebooking strategy.
Task 6: Calculate compensation.
Task 7: Generate final recommendation.
```

The planner creates dependencies between tasks to ensure that each step receives the required information from previous steps.

---

### 5. Planner Selection

When a task requires complex reasoning, the system selects an appropriate planning strategy.

**Available strategies:**

**Plan-and-Solve**

Used for straightforward multi-step decisions.

```
Collect passenger data
  → Check alternatives
  → Apply compensation rules
```

**Tree of Thoughts**

Used when multiple possible solutions exist.

```
Option A: Rebook passenger on another flight.
Option B: Provide alternative transportation.
Option C: Offer refund and compensation.
```

The system evaluates the alternatives and selects the best one.

**LATS (Language Agent Tree Search)**

Used for tasks requiring exploration and environment feedback.

The planner:
1. Generates possible actions.
2. Executes candidates.
3. Receives feedback.
4. Selects the best path.

---

### 6. Execution Through MCP Tools

After generating the plan, tasks are executed through the MCP architecture.

Execution flow:

```
Planning Agent
      |
      v
  MCP Client
      |
      v
  MCP Server
      |
      v
Available Tools
      |
      v
   Database
```

Examples of executed operations:
- Retrieve flight information.
- Find affected bookings.
- Check customer details.
- Search available alternatives.
- Calculate refunds.
- Issue compensation.

All actions are grounded in real stored data.

---

### 7. Policy Retrieval and Memory Usage

During decision-making, the system can use additional knowledge sources.

**RAG Layer**

The retrieval system provides relevant airline policies such as:
- Cancellation rules.
- Compensation policies.
- Rebooking conditions.

**Memory Layer**

The memory system helps maintain useful information:
- Current conversation context.
- Previous customer interactions.
- Stored facts and preferences.

---

### 8. Grounded Evaluation

After generating a recommendation, the system evaluates the result using the travel environment.

The evaluation checks:
- Is the recommendation valid?
- Does it follow available options?
- Does it respect company rules?
- Is it supported by database information?

If improvement is needed, the system can use:
- Self-Refine.
- Reflexion.

to revise the generated answer.

---

### 9. Final Recommendation

The system provides a final recommendation to the airline operator.

Example:

```
Flight 2 is delayed by 120 minutes due to bad weather.

Affected passengers:
- Passenger A (VIP)
- Passenger B

Recommended actions:
- Passenger A: Rebook to alternative flight MS303.
- Passenger B: Provide compensation voucher according to policy.

Reason:
The recommendation satisfies passenger priority,
available alternatives, and airline rules.
```

## Expected Benefits

The WanderPathA system helps airline teams by:
- Reducing manual disruption handling time.
- Making decisions based on real operational data.
- Providing explainable planning steps.
- Selecting suitable reasoning strategies depending on task complexity.
- Improving reliability through evaluation and feedback loops.

---

## Conclusion

This use case demonstrates how WanderPathA transforms a simple customer disruption request into an autonomous decision-making workflow.

Instead of relying on a single LLM response, the system combines planning, MCP-based execution, retrieval, memory, and grounded evaluation to produce reliable recommendations for complex airline operations.
